# 更新后的应用构想：光伏项目可行性研究报告生成系统

## 1. 项目背景

本项目旨在开发一个专门用于生成《光伏项目可行性研究报告》的网页应用，基于对行业标准的深入分析，针对光伏行业专业文档的生成需求，提供高度专业化、符合行业规范的文档生成服务。与通用文档生成系统不同，本应用专注于光伏项目可行性研究报告的生成，确保内容专业、格式规范、符合行业标准。

## 2. 目标用户

- 光伏项目开发商
- 光伏电站设计院
- 工程公司技术部门
- 项目投资决策人员
- 电力系统规划部门

## 3. 需求更新

### 3.2 专业规范与数据要求

基于PDF内容，确定必须包含的专业规范和数据：

```
- 引用《建筑结构荷载规范》GB50009-2012
- 引用《光伏发电站设计规范》GB50797-2012
- 引用《钢结构设计标准》GB50017-2017
- 项目荷载要求：允许施工或检修集中荷载为1kN
- 电池组规格：2382×1134×30mm
- 结构设计年限：25年，安全等级：二级
- 建筑物安全等级：二级，场地类别：Ⅱ类
- 钢材规格：Q235B/Q355B/S250GD/S350GD级钢
- 焊条规格：E43，E50
- 防腐要求：热镀锌，锌膜厚度不小于65μm
- 冬季施工要求：
  * 焊接：清除铁锈、污物，焊后接头应用干砂缓慢冷却
  * 混凝土：添加防冻剂，水温不超过80℃，入模温度不低于10℃
  * 砌体工程：砂浆用普通硅酸盐水泥，砖应清除冰霜
  * 钢结构：负温下焊接需选用低氢型焊条
```

### 3.3 用户输入与数据收集

基于PDF内容，设计专门的输入字段，确保生成内容的专业性和准确性：

```
1. 项目基本信息
   - 项目名称（必填）
   - 项目地点（必填）
   - 项目规模（kW）（必填）
   - 项目地点经纬度（可选，用于气象数据参考）

2. 技术参数
   - 光伏组件规格（必填）
   - 电池板尺寸（必填，如2382×1134×30mm）
   - 系统设计年限（默认25年）
   - 结构安全等级（默认二级）
   - 地点气候条件（如成都，可选：寒冷地区、温和地区等）
   - 建筑物类型（厂房屋顶、商业建筑等）

3. 施工条件
   - 施工季节（必填，如冬季、夏季等）
   - 钢材类型（必填，如Q235B/Q355B等）
   - 防腐要求（必填，如热镀锌等）
   - 特殊施工要求（如冬季施工措施等）

4. 财务数据
   - 初始投资估算（万元）（必填）
   - 年发电量（kWh）（必填）
   - 电价（元/kWh）（必填）
   - 运维成本（万元/年）（必填）
```

## 5. 技术架构（保持不变）

后端架构：后端采用 Node.js 作为主要开发框架。

AI 模型调用与数据处理逻辑实现：AI模型使用MinimaxM2的模型，模型文档储存在：MiniMax调用文档.md中集成 Typst 排版引擎，支持 Typst 源文档的编译与 PDF 导出。

API 接口：提供 RESTful API，允许前端与后端交互，生成文档、获取预览、下载 PDF 等。

文档生成流程：
1. 用户输入数据
2. 后端调用AI模型生成报告内容
3. Typst排版引擎将内容转换为PDF
4. 提供PDF下载

## 6. 优势与价值

1. **高度专业化**：专注于光伏项目可行性研究报告，内容符合行业规范，无需用户调整格式。

2. **数据驱动**：基于光伏项目实际参数，确保报告内容准确可靠。

3. **符合行业标准**：严格引用相关规范，确保报告的专业性和权威性。

4. **效率提升**：将原本需要数天完成的可行性研究报告编写，缩短至几分钟。

5. **降低错误率**：避免人工编写时可能遗漏的技术规范和数据。

6. **专业形象**：生成的报告专业、规范，提升用户在行业内的专业形象。

## 8. 结论

本应用构想已根据《广州发展成都广日科技有限公司屋顶分布式光伏项目--可行性研究报告》的详细内容进行了全面更新和优化，专注于光伏项目可行性研究报告的生成。系统将确保生成的文档专业、规范、符合行业标准，同时保持原有的技术架构不变，确保系统的高效性和稳定性。
## 技术选型

- **前端**：ReactUI 框架，支持动态交互和文档预览）
- **后端**：Node.js
- **排版引擎**：Typst 引擎（通过 Typst API 或 CLI 进行文档编译）
- **AI 模型**：MiniMax系列（用于内容生成）
- **数据库**：PostgreSQL（存储用户数据、历史文档、模板等）
- **用户界面**：隐藏typst语法和包体，用户只需要填写简单的字段或上传数据文件，即可生成文档。
- **界面设计**：参考GitHubcopilot这种工作台的形式来安排，中间是文档的预览和编辑页面，用户编辑要求可视化编辑，即用户可以在编辑页面直接看到文档的排版效果。页面右侧是用户和AI对话的区域，用户可以在这个区域与AI进行交互，例如询问问题、请求修改等。
